# Плейлисты, M3U/IPTV и эфирный режим

## Откуда берется плейлист

1. **Intent** (`IntentUtils.parseIntent`) — одиночный файл или `video_list`, см. [INTENT_API.md](INTENT_API.md).
2. **Одиночная ссылка `.m3u`/`.m3u8`** из Intent — плеер проверяет, не плейлист ли это.
3. **Плейлисты по ссылке на стартовом экране** (`saved_playlists`: название и ссылка; прежний стартовый плейлист
   `startup_playlist_uri` переносится сюда один раз). Проверка на M3U делается принудительно (`forceM3uProbe = true`,
   ключ `EXTRA_FORCE_M3U`), потому что у таких ссылок часто нет расширения (`get.php?...`).

## M3U-проба (`PlayerManager.expandM3u`)

- Проверяется только одиночная ссылка, путь которой заканчивается на `.m3u`/`.m3u8` (или любая при `force`).
- http(s) скачивается **один раз** (`fetchForProbe`), остальное читается через `ContentResolver`.
  Лимит — `MAX_PROBE_BYTES` (32 МБ). Content-Type `video/*` и `audio/*` сразу означает «не плейлист».
- `M3uParser.isPlaylist`: есть `#EXTINF` и **нет ни одного** `#EXT-X-`. Любой HLS-тег означает HLS.
- Если это не M3U, ответ кладется в `PrefetchStore`, и плеер получает его без второго запроса.
  Если в тексте есть `#EXT-X-`, тип сразу помечается как HLS (`probedMediaTypes`).

## M3uParser

- `#EXTINF:<attrs>,<title>`: название — все после первой запятой **вне кавычек**.
  Атрибуты: `tvg-logo`/`logo` (постер), `group-title` (группа).
- `#EXTGRP:` задает группу по умолчанию для следующих элементов, если у них нет `group-title`.
- `#EXTVLCOPT:http-user-agent|http-referrer|http-referer|http-cookie` и `#EXTHTTP:{json}` задают
  заголовки следующего элемента. Они объединяются с заголовками родительской ссылки.
- Относительные пути разрешаются от URI плейлиста.

## Состояние плейлиста в PlayerViewModel

- `currentPlaylist` — полный список. У каждого элемента есть `absoluteIndex`, это номер в полном списке.
- `playlistUiState` (`PlaylistUiState`) хранит отображаемые элементы с фильтром по группе, текущую группу
  и список групп. В диалоге плейлиста группы переключаются кнопками Влево/Вправо (`cycleGroup`, есть пункт «Все»)
  и выбираются в диалоге групп (`selectGroup`). Если группу сменили, но ничего не выбрали, после закрытия
  возвращается группа текущего элемента (`revertToPlayingGroup`).
- `isM3uPlaylist` — плейлист пришел из M3U.

## Последний канал

Работает только для M3U-плейлиста: при каждом переходе URI сохраняется в `last_channel_uri`.
При следующей загрузке M3U стартовый элемент ищется **по точному URI**. Если не нашелся, плеер начинает с первого.
Плейлисты из Intent этой логики не касаются.

## Эфирный режим (live mode)

`isOverallLiveMode()` возвращает true, только если выполнены все три условия:
1. в настройках включен `live_mode_control` (**по умолчанию выключен**);
2. в плейлисте больше одного элемента;
3. в текущем плейлисте уже играл live-поток (`isSessionLive`). Подходит и M3U, и любой другой плейлист.

В эфирном режиме, когда панель управления скрыта, кнопки работают так (`PlayerInputHandler`):
- **OK** открывает плейлист;
- **Влево/Вправо** переключают канал (`zapChannel`): название канала показывается сразу, а сам канал
  включается через 1.5 с после последнего нажатия. Так можно пролистать несколько каналов подряд.
  OK включает выбранный канал сразу (`confirmZap`), любая другая кнопка отменяет выбор (`stopZap`).
- **Вверх** показывает инфопанель, а повторное нажатие открывает боковое меню.
- Инфопанель показывается при каждой смене канала. Вне эфирного режима это делается по настройке
  `show_info_on_change`.

На телефоне в эфирном режиме горизонтальный свайп листает каналы текущей группы по кругу
(`PlayerFragment.handleHorizontalSwipe`), а тап по верхней зоне открывает плейлист.

## Продолжение просмотра (`handleResumeLogic`)

Работает только для **первого** элемента нового плейлиста (`isFirstItemLoaded`) и не работает для live.

1. **Позиция от внешнего приложения** (`position` в Intent) приоритетнее сохраненной в плеере:
   - `external_position_mode = APPLY` (по умолчанию): плеер сразу стартует с этой позиции;
   - `= ASK`: плеер стартует с 0, а позиция хранится в `pendingExternalPosition` (вместе с uuid элемента)
     и предлагается в диалоге продолжения.
2. Иначе используется **сохраненная позиция** из Room (`VideoSettings.lastPosition`) по `resume_mode`:
   спросить (по умолчанию), всегда или никогда.
3. Позиция осмысленна, если она не меньше 5 с и не больше 95 % длительности (`isResumePositionMeaningful`).
